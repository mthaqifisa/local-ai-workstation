## 3 Specific Optimization Actions

### Action 1 — Clean up `~/Library` (50 GB — your largest folder)

Your Library folder is consuming **50 GB**, which is 87% of your home directory usage. The usual culprits:

```bash
# Check what's eating space inside Library
du -sh ~/Library/Caches/* 2>/dev/null | sort -rh | head -10
du -sh ~/Library/Developer/* 2>/dev/null | sort -rh | head -5
du -sh ~/Library/Application\ Support/* 2>/dev/null | sort -rh | head -10
```

**Likely savings:** 10–30 GB from stale caches (Chrome, Xcode derived data, Docker/Colima images, Homebrew caches).

### Action 2 — Tame Chrome's GPU process (46.3% CPU)

The Chrome GPU helper is your single biggest CPU consumer at **46.3%**. This is often caused by:
- Hardware-accelerated video playback (YouTube, streaming tabs)
- GPU-intensive web apps or AI demos running in-browser
- Too many open tabs with canvas/WebGL content

**Fix:** Close unused Chrome tabs, or disable hardware acceleration for non-critical work:
`Chrome → Settings → System → "Use graphics acceleration when available" → OFF` (then relaunch).

### Action 3 — Investigate the MLX Stack / OpenClaw crash-looping services

Three services are repeatedly crashing:

| Service | Status |
|---|---|
| `com.mlxstack.colima` | -9 (killed) |
| `com.mlxstack.dashboard` | -9 (killed) |
| `ai.openclaw.gateway` | 78 (error exit) |

These are consuming CPU cycles in a crash-restart loop. If you're not actively using MLX Stack or OpenClaw right now, stop them:

```bash
launchctl unload ~/Library/LaunchAgents/com.mlxstack.colima.plist 2>/dev/null
launchctl unload ~/Library/LaunchAgents/com.mlxstack.dashboard.plist 2>/dev/null
launchctl unload ~/Library/LaunchAgents/ai.openclaw.gateway.plist 2>/dev/null
```

If you need them, check their logs for the root cause:
```bash
log show --predicate 'process == "colima"' --last 1h --info
```
