## Key Findings

### Scalability to 10M Users
- **75K peak concurrent editors** across **150K WebSocket connections**
- **562K operations/sec** at peak, requiring **3 WebSocket nodes** (50K conn/node)
- **21 TB total storage** (CRDT format, 30-day version retention)
- **~$2.9M/mo infra cost** ($0.29/user/month)

### CRDT vs OT Decision
**Chose CRDT (Yjs)** over OT. Key reasons: offline-first support, character-level granularity, multi-region native convergence. Trade-off: 40% more storage (~$137K/mo extra) for significantly better UX.

### Architecture Highlights
- **WebSocket servers** (Node.js) relay CRDT ops via Yjs protocol
- **API service** (Go) handles CRUD, auth, permissions
- **Redis Cluster** (6 shards × 3 replicas) for real-time state, presence, op buffering
- **PostgreSQL + S3** hybrid: metadata in RDS, document blobs in S3 (79% storage cost savings)
- **Latency budget:** 100ms p95 (20ms WS RTT + 5ms CRDT + 2ms Redis + 50ms async DB)

### Top Risks
1. PostgreSQL storage cost explosion → tiered storage, compression, shorter retention
2. WebSocket fan-out bottleneck → Redis pub/sub broadcast, document affinity routing
3. CRDT merge conflicts → Yjs proven convergence, snapshot backup strategy
